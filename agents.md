# Project Agents Guide

Этот файл описывает текущее состояние проекта и задаёт локальные правила работы Codex для каталога `D:\Проекты\Сайт\Сайт`.

## Текущее состояние проекта

Сейчас проект представляет собой статический промо-лендинг для компании КонсольГрад. В корне проекта лежат HTML, CSS и JavaScript-файлы без framework-зависимостей и без обязательного шага сборки. Страница открывается локально как обычный статический сайт и служит первой продающей витриной бизнеса.

## Стек проекта

Текущий стек по содержимому проекта:

- `index.html` — точка входа лендинга
- `styles.css` — визуальная система, адаптивность, анимации и оформление
- `script.js` — reveal-анимации, tilt-эффекты, счётчики и фоновая canvas-анимация
- `.codex/config.toml` — локальная конфигурация Codex
- `.codex/agents/*.toml` — специализированные агентские профили
- `.agent/PLANS.md` — правила ведения ExecPlan
- `execplan-landing.md` — текущий ExecPlan по разработке лендинга
- `agents.md` — проектные инструкции для Codex

Пока не добавлены:

- frontend-framework
- package manager-манифест (`package.json`, `pyproject.toml`, `Cargo.toml` и т.д.)
- отдельный тестовый раннер
- production-сборка и pipeline деплоя

## Команды запуска и сборки

Проект пока не требует сборки.

Актуальные команды:

- Открыть Codex в корне проекта: `codex`
- Проверить локальные настройки после запуска Codex: `/status`
- Проверить, что подхватились агенты и проектный документ: `/agents`
- Запустить локальный статический сервер для просмотра сайта: `python -m http.server 4173`
- После запуска открыть страницу по адресу: `http://127.0.0.1:4173/index.html`

Если позже в проект будет добавлен framework или bundler, этот раздел нужно обновить и зафиксировать команды разработки, сборки и тестирования.

## Правила кода

- Работай только внутри корня текущего проекта и его подпапок.
- Предпочитай минимальные, точечные и обратимо-безопасные изменения.
- Перед существенными изменениями сначала изучай существующие файлы, а не угадывай структуру.
- Если в проекте появится устоявшийся стиль, следуй ему, а не вводи новый без причины.
- Не добавляй зависимости и инструменты без явной необходимости.
- Для лендинга сохраняй сильную игровую подачу, но не жертвуй читаемостью, мобильной адаптацией и B2B-понятностью оффера.
- Не заявляй спорные юридические обещания вокруг аккаунтов, подписок и прав на контент, если это явно не подтверждено.
- Если в задаче есть нетривиальная архитектурная работа, сначала создай или обнови ExecPlan.
- Если текущая задача упирается в недостающий стек проекта, сначала явно зафиксируй это в ответе и только затем предлагай следующий шаг.

## Самопроверка

Перед завершением любой заметной задачи агент должен:

- проверить, что изменены только релевантные файлы внутри этого проекта;
- перечитать собственные изменения и убедиться, что они согласованы с текущей структурой;
- выполнить доступные локальные проверки проекта, если они существуют;
- для статического лендинга как минимум проверить HTTP-отдачу страницы через локальный сервер;
- если проверок пока нет, явно указать, что автоматическая валидация недоступна;
- описать наблюдаемый результат и любые оставшиеся риски.

## ExecPlans

When writing complex features or significant refactors, use an ExecPlan (as described in `.agent/PLANS.md`) from design to implementation.

ExecPlan должен быть самодостаточным, вестись как живой документ и обновляться по мере принятия решений, появления открытий и продвижения работы.

## Примечание по доступу

Проект настроен так, чтобы Codex использовал проектный документ `agents.md`, работал в режиме `workspace-write` и имел включённый `network_access` в конфигурации `.codex/config.toml`, при этом запись ограничена корнем текущего проекта.
